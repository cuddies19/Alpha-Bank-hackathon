# Кредитный кабинет — фронтенд

Кабинет клиента и консоль кредитного аналитика. React 19 + TypeScript 6 (strict) + Vite 8, React Router 7, TanStack Query 5

## Запуск

Всё вместе в Docker, из корня репозитория: `docker compose up --build` → <http://localhost:3000>. Образ: `frontend/Dockerfile` (сборка на Node 22.14.0 и nginx, конфиг `frontend/nginx.conf`).

Для разработки:

```bash
docker compose up -d   # из корня репозитория: бэкенд на http://localhost:8000
npm install
npm run dev            # http://localhost:5173
npm run build          # проверка типов и сборка в dist/
npm run lint           # oxlint
npm run format         # prettier
npm run api:types      # пересобрать src/shared/api/schema.ts из docs/openapi.json
```

Нужен Node 22.12+. React Router взят из ветки 7: восьмая требует Node 22.22+.

### Настройки сборки

Все переменные с префиксом `VITE_` попадают в JS и видны любому посетителю. Секреты в них не кладём.

| Переменная | Значения | По умолчанию |
| --- | --- | --- |
| `VITE_API_MODE` | `api` — бэкенд через прокси `/api` → `localhost:8000`; `mock` — моки в браузере | `api` |
| `VITE_FEATURE_DEMO` | `true` / `false` — быстрый выбор тестовых пользователей на входе, «Режим проверки», кнопка «войти как клиент» | включён в `npm run dev`, выключен в `npm run build` |
| `VITE_DEMO_PASSWORD` | пароль тестовых пользователей бэкенда для быстрого входа | не задан |

Флаги лежат в `src/shared/config/features.ts`, в коде проверяются как `features.demo`. Новый флаг — новая строка в объекте `features` и в `src/vite-env.d.ts`.

Для локальной разработки создайте `frontend/.env.development` (в git не попадает):

```
VITE_FEATURE_DEMO=true
VITE_DEMO_PASSWORD=demo123
```

Сборка для демо-стенда: `VITE_FEATURE_DEMO=true VITE_DEMO_PASSWORD=demo123 npm run build`. Прод-сборка — просто `npm run build`: без флага в ней нет ни пароля, ни демо-инструментов.

Моки без бэкенда: `VITE_API_MODE=mock npm run dev`, пароль тестовых пользователей — `demo-2026`. Сценарии демо ниже полностью работают в этом режиме.

«Режим проверки» (кнопка с пунктиром внизу меню) — инструмент жюри. В нём можно:
- войти любым пользователем, в том числе «Игорь — после решения банка»;

- сбросить демо-данные.

## Архитектура

Слои по [Feature-Sliced Design](https://feature-sliced.design/): импорт разрешён только сверху вниз.

```
src/
  app/        провайдеры, роутер, каркасы разделов (ClientLayout, BankLayout), охрана ролей, глобальные стили и токены
  pages/      страницы — одна папка на экран, грузятся отдельными чанками
  widgets/    крупные блоки: меню, шапки, панель ассистента, панель решения, шапка карточки заявки, график платежей
  features/   действия пользователя: вход (auth), режим проверки (demo-mode)
  entities/   предметная область: заявка, компания, продукт, счёт, кредит, документ, уведомление, источник, аудит
  shared/     дизайн-система (ui), утилиты (lib), адреса страниц (config), клиент API (api)
  mocks/      мок-бэкенд: данные и логика сервера в памяти браузера
```

## Данные: API и моки

Запросы идут из `entities/<сущность>/api`. В каждом файле две реализации — HTTP и моки, выбор по `USE_API` из `shared/config`. Хуки React Query и страницы от режима не зависят.

- `shared/api/http.ts` — `fetch` с токеном из `sessionStorage`, ошибки бэкенда `{code, message}` превращаются в `ApiError`. На 401 сессия сбрасывается.
- `shared/api/schema.ts` — типы ответов, генерируются из `docs/openapi.json`. Руками не правится.
- Переходники «ответ API → модель фронта» лежат рядом с запросами. Главный — `entities/application/api/httpApplicationApi.ts`.
- У заявки два идентификатора: `id` — числовой id бэкенда, в адресах страниц; `number` — `2026-10-0001`, его видит пользователь.

| Что | Откуда в режиме `api` |
| --- | --- |
| Вход, сессия | `POST /auth/login`, `GET /me` |
| Продукты, подбор | `GET /products`, `POST /recommendations`, `GET /me/cashflow`. Тексты описаний продуктов — фронтовые |
| Заявки клиента | `/applications/*`: создание, черновик, документы, отправка, отзыв, принятие, отказ, подписание, повторная подача |
| Консоль банка | `/bank/applications/*`, `/bank/audit`, `/bank/sources` |
| Счёт на главной | `GET /me/cashflow` |
| Уведомления, кредиты | `GET /notifications`, `GET /loans` |
| Ассистент | `POST /assistant/chat`. Режим «на правилах» — локальные шаблоны |
| Режим проверки | `/demo/*`: источники, скорость, сброс |

Пока на моках, потому что у бэкенда нет эндпоинтов:
- экраны «Конвейер» и «Продукты и правила»;
- настройки уведомлений и отзыв согласий в профиле;
- сценарий «Игорь — после решения банка» в режиме проверки (в режиме `api` скрыт);
- удаление загруженного файла — в режиме `api` кнопки нет.

Чего не хватает в данных бэкенда:
- конвейер (`backend/app/pipeline`) пустой. Поданная заявка ждёт, пока аналитик нажмёт «Взять в работу»; проверок, скоринга и правил в карточке нет;
- для аналитика нет денежного потока компании — шкала нагрузки в панели решения скрыта;
- нет номера счёта, сотрудников, расшифровки ОКВЭД — эти поля не показываются.

В режиме `mock` состояние хранится в `sessionStorage`, поэтому сценарий переживает перезагрузку страницы.
