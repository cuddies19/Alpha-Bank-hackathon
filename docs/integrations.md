# Контракты внешних источников

Четыре источника, которые конвейер опрашивает при обогащении заявки. Все они симулированные (сервис `mocks/`, порт 8090).
Данные нужны DS для признаков скоринга и Core для таблицы `source_checks`.

**Контракты упрощены.** Реальные форматы БКИ и ФНС намного сложнее (другие поля, вложенность, подпись, согласия, асинхронная выдача). Здесь только то, что нужно для демо и скоринга.

## Общие правила

- Деньги: целые рубли (`int`), поля заканчиваются на `_rub`. Копеек нет.
- Даты: ISO 8601. День `YYYY-MM-DD`, месяц `YYYY-MM`.
- Имена полей в JSON: snake_case, латиницей.
- Неизвестный ИНН не даёт 404. Мок генерирует данные из ИНН (один ИНН — всегда одни и те же данные). Демо-клиенты заданы руками, см. ниже.
- Таймаут одного запроса по умолчанию 3 с, всего 3 попытки. Если все попытки неудачны, конвейер ставит проверке статус «не ответил» и отправляет заявку на ручное рассмотрение. Заявка не падает.
- Таймаут и число попыток задаются в `.env` конвейера (по умолчанию 3 попытки по 3 с). Текст для экрана C2 вроде «БКИ не ответило, 3 попытки по 3 с» собирает бэкенд из реальных значений, фронт показывает его как есть.

## Ошибки (для всех источников)

| Ситуация | Что отдаёт мок | Что делает конвейер |
|---|---|---|
| Режим `error` | HTTP 500, `{"detail": "source error"}` | повтор, после 3 попыток — «не ответил» |
| Режим `down` | мок не отвечает (запрос висит дольше таймаута клиента) | таймаут, повтор, после 3 попыток — «не ответил» |
| Режим `slow` | ответ через `delay_ms` (по умолчанию дольше таймаута) | таймаут, повтор, после 3 попыток — «не ответил» |
| Плохой ИНН (не 10 и не 12 цифр) | HTTP 422 | повтор не нужен, проверка помечается ошибкой данных |

## ЕГРЮЛ / ЕГРИП

Зачем: подтвердить, что бизнес существует, его статус, дату регистрации и вид деятельности. Нужен для правил «возраст бизнеса от 12 месяцев» и «действующее».

Запрос: `GET /egrul/{inn}`

Ответ 200:

| Поле | Тип | Пример | Описание |
|---|---|---|---|
| `inn` | string | `"7701234567"` | ИНН (10 цифр для ЮЛ, 12 для ИП) |
| `ogrn` | string | `"1247700123456"` | ОГРН, 13 цифр. Только для `ul` |
| `ogrnip` | string | `"322774600123456"` | ОГРНИП, 15 цифр. Только для `ip` |
| `entity_type` | string | `"ul"` | `ul` или `ip` |
| `full_name` | string | `"ООО «Дом и уют»"` | Название |
| `status` | string | `"active"` | `active`, `liquidating`, `liquidated` |
| `registration_date` | string | `"2024-06-12"` | Дата регистрации |
| `okved` | string | `"47.91"` | Основной ОКВЭД |
| `address` | string | `"г. Москва, ул. Тверская, д. 10"` | Адрес |
| `head_name` | string | `"Соколов И. А."` | Руководитель (для ИП — сам предприниматель) |

Пример:

```json
{
  "inn": "7701234567",
  "ogrn": "1247700123456",
  "entity_type": "ul",
  "full_name": "ООО «Дом и уют»",
  "status": "active",
  "registration_date": "2024-06-12",
  "okved": "47.91",
  "address": "г. Москва, ул. Тверская, д. 10",
  "head_name": "Соколов И. А."
}
```

## ФНС «Прозрачный бизнес»

Зачем: налоговая задолженность, недостоверный адрес, доходы и расходы, численность. Нужен для стоп-правил («нет налоговой задолженности») и признаков скоринга.

Запрос: `GET /fns/{inn}`

Ответ 200:

| Поле | Тип | Пример | Описание |
|---|---|---|---|
| `tax_debt_rub` | int | `0` | Задолженность по налогам |
| `address_unreliable` | bool | `false` | Есть отметка о недостоверности адреса |
| `income_last_year_rub` | int | `44800000` | Доходы за прошлый год |
| `expenses_last_year_rub` | int | `41900000` | Расходы за прошлый год |
| `avg_headcount` | int | `6` | Среднесписочная численность |
| `tax_regime` | string | `"usn_income"` | `osno`, `usn_income`, `usn_income_expense`, `patent`, `esn` |
| `mass_director` | bool | `false` | Руководитель числится в десятках компаний |

Пример:

```json
{
  "tax_debt_rub": 0,
  "address_unreliable": false,
  "income_last_year_rub": 44800000,
  "expenses_last_year_rub": 41900000,
  "avg_headcount": 6,
  "tax_regime": "usn_income",
  "mass_director": false
}
```

## БКИ (бюро кредитных историй)

Зачем: действующие кредиты, просрочки, количество запросов истории. Нужен для долговой нагрузки и стоп-правила по просрочке.

Запрос: `POST /bki/report`

```json
{ "inn": "7701234567", "consent_id": "cns-2026-10-0142" }
```

`consent_id` — идентификатор согласия клиента на запрос истории. Мок его не проверяет, но поле обязательно (без него 422).
Сейчас у согласий нет своего id (в заявке только флаги `consents`), поэтому конвейер передаёт сюда номер заявки. Для настоящего БКИ нужно завести id согласия при подписании.

Ответ 200:

| Поле | Тип | Пример | Описание |
|---|---|---|---|
| `loans` | array | см. ниже | Действующие кредиты в других банках. Пустой массив, если их нет |
| `loans[].bank` | string | `"Банк Пример"` | Банк |
| `loans[].balance_rub` | int | `450000` | Остаток долга |
| `loans[].monthly_payment_rub` | int | `38000` | Платёж в месяц |
| `max_overdue_days_12m` | int | `0` | Максимальная просрочка за 12 месяцев, дней |
| `max_overdue_days_24m` | int | `0` | То же за 24 месяца |
| `inquiries_30d` | int | `2` | Сколько раз запрашивали историю за 30 дней |

Пример:

```json
{
  "loans": [
    { "bank": "Банк Пример", "balance_rub": 450000, "monthly_payment_rub": 38000 }
  ],
  "max_overdue_days_12m": 0,
  "max_overdue_days_24m": 0,
  "inquiries_30d": 2
}
```

## Выписка по счёту

Зачем: обороты по счёту за период. Нужна для среднего чистого потока (от него считается доля платежа), сезонности и доли выручки, уходящей в другой банк.

Запрос: `GET /statement/{inn}?months=12`

`months` — сколько последних месяцев вернуть (по умолчанию 12).

Ответ 200:

| Поле | Тип | Пример | Описание |
|---|---|---|---|
| `months` | array | см. ниже | По одному элементу на месяц, от старого к новому |
| `months[].month` | string | `"2026-09"` | Месяц `YYYY-MM` |
| `months[].inflow_rub` | int | `3900000` | Поступления за месяц |
| `months[].outflow_rub` | int | `3290000` | Списания за месяц |
| `balance_rub` | int | `1240500` | Остаток на счёте сейчас |
| `avg_net_flow_rub` | int | `610000` | Средний чистый поток за месяц (поступления минус списания) |
| `marketplace_share` | number | `0.85` | Доля поступлений от маркетплейсов, 0..1 |
| `revenue_to_other_bank` | bool | `false` | Часть выручки идёт на счёт в другом банке |
| `inflow_30d_rub` | int | `3860000` | Поступления за последние 30 дней |

Пример (месяцы сокращены):

```json
{
  "months": [
    { "month": "2026-08", "inflow_rub": 3700000, "outflow_rub": 3090000 },
    { "month": "2026-09", "inflow_rub": 3900000, "outflow_rub": 3290000 }
  ],
  "balance_rub": 1240500,
  "avg_net_flow_rub": 610000,
  "marketplace_share": 0.85,
  "revenue_to_other_bank": false,
  "inflow_30d_rub": 3860000
}
```

## Скоринг DS

Контракт согласован с DS. Эндпоинт `POST /score` живёт в API (`backend/app/api/score.py`, расчёт в `backend/app/services/scoring.py`), конвейер вызывает его из `backend/app/pipeline/scoring.py`. Адрес задаёт `PIPELINE_SCORING_URL` (в compose по умолчанию `http://api:8000`); если он пуст, берётся заглушка (640, класс B).

Запрос: `POST /score`

```json
{
  "inn": "7701234567",
  "features": {
    "business_age_months": 16,
    "income_last_year_rub": 44800000,
    "tax_debt_rub": 0,
    "max_overdue_days_12m": 0,
    "max_overdue_days_24m": 0,
    "inquiries_30d": 2,
    "avg_net_flow_rub": 610000,
    "marketplace_share": 0.85,
    "revenue_to_other_bank": false,
    "monthly_payments_rub": 38000
  }
}
```

Признаки собираются из ответов источников. Если данных нет, значение `null`.

Ответ 200:

```json
{ "score": 640, "risk_class": "B" }
```

- `score` — целое число от 300 до 850, `risk_class` — одна из `A`, `B`, `C`, `D`, `E`. Иначе ответ считается непонятным.
- Все 10 признаков обязательны. Если признак `null` (источник не ответил), скоринг вернёт 422, и заявка уйдёт на ручное рассмотрение.
- Классы демо-клиентов: Соколов B, Белова B, Орлова B, Фомин D.
- Таймаут и число попыток те же, что у источников. Ошибка 5xx или таймаут — повтор; 4xx — без повтора.
- Скоринг не ответил или ответ непонятный: заявка уходит на ручное рассмотрение.

## Админка моков

Чтобы показать на демо, что сбой источника не роняет заявку.

| Метод и путь | Что делает |
|---|---|
| `GET /health` | `{"status": "ok"}`. Для compose и проверок |
| `GET /_admin/sources` | Текущий режим каждого источника |
| `POST /_admin/sources/{source}` | Меняет режим источника |

`{source}`: `egrul`, `fns`, `bki`, `statement`.

Тело `POST`:

```json
{ "mode": "slow", "delay_ms": 5000 }
```

- `mode`: `ok` (по умолчанию), `slow` (ответ с задержкой), `down` (не отвечает, запрос висит до таймаута клиента), `error` (HTTP 500).
- `delay_ms` — только для `slow`. Если не задан, задержка 4000 (дольше таймаута 3 с).
- Стартовые режимы задаются в `.env`: `MOCKS_DEFAULT_MODES=bki=down,fns=slow`.
- `POST /_admin/sources/_reset` — вернуть стартовые режимы.
- У каждого ответа источника есть заголовок `X-Mock-Latency-Ms` — сколько мок «думал» (случайно 100–600 мс плюс задержка режима).

Ответ `GET /_admin/sources`:

```json
{
  "egrul": { "mode": "ok", "delay_ms": null },
  "fns": { "mode": "slow", "delay_ms": 4000 },
  "bki": { "mode": "down", "delay_ms": null },
  "statement": { "mode": "ok", "delay_ms": null }
}
```

Неизвестный `source` — 404, неизвестный `mode` — 422. Режимы живут в памяти и сбрасываются при перезапуске мока.
